# 渲染扩展

## 两类扩展方式

渲染扩展需要先区分两个概念。

### 1. 复用现有渲染器

例如：

- 点弹幕用 `model_json`
- 激光用 `laser_poly`

这种情况下通常不需要注册新渲染器，只需要：

- 选择已有 `rendererType`
- 通过 `customData` 传参数

### 2. 注册新的渲染器类型

这种情况下才需要：

- 新写渲染器类
- 在客户端初始化时注册
- 在 Builder 中使用新的 `rendererType`

## 点弹幕渲染器

注册表：

- `RendererRegistry`

接口：

- `IBulletRenderer`

内置类型：

- `billboard`
- `point`
- `model_json`

## 激光渲染器

注册表：

- `LaserRendererRegistry`

接口：

- `ILaserRenderer`

内置类型：

- `laser_beam`
- `laser_blast`
- `laser_none`
- `laser_poly`

## 注册新的点弹幕渲染器

步骤：

1. 实现 `IBulletRenderer`
2. 在客户端初始化时注册到 `RendererRegistry`
3. 通过 `rendererType("your_type")` 使用

示意：

```java
RendererRegistry.register("my_renderer", data -> new MyRenderer());
```

注意：

- 注册只能放在客户端初始化阶段
- 不要在公共服务端逻辑里直接引用客户端渲染类

## 注册新的激光渲染器

步骤：

1. 实现 `ILaserRenderer`
2. 注册到 `LaserRendererRegistry`
3. 在激光 Builder 中使用新的 `rendererType`

示意：

```java
LaserRendererRegistry.register("my_laser", data -> new MyLaserRenderer());
```

## 复用 `model_json`

`model_json` 渲染器会从 `customData` 读取：

- `model`
- `variant`
- `scale`
- `rot_mode`
- `tint`

示例：

```java
BulletApi.builder(world)
    .position(pos)
    .velocity(vel)
    .rendererType("model_json")
    .set("model", "minecraft:furnace")
    .set("variant", "inventory")
    .set("scale", 0.45f)
    .set("rot_mode", "velocity")
    .set("tint", 0x66CCFF)
    .spawn();
```

这里不是注册新渲染器，而是复用现有渲染器切换模型资源。

## `model_json` 旋转模式

当前常用：

- `velocity`
  - 按速度方向旋转
- `face_camera`
  - 始终朝向摄像机
- `fixed`
  - 使用固定 yaw/pitch/roll

## 激光视觉参数

激光渲染器通过 `customData` 读参数。

例如 `laser_poly` 常见字段：

- `alpha`
- `poly_sides`
- `core_scale`
- `shell_scale`
- `pulse_amp`
- `pulse_speed`
- `shell_color`
- `shell_color_end`

例如 `laser_blast` 常见字段：

- `segment_len`
- `core_scale`
- `shell_scale`
- `shell_color`
- `shell_color_end`

## 常见问题

### 为什么 `rendererType` 没生效

通常是：

- 对应类型没有注册
- 注册只发生在客户端，但你实际上没有走到客户端初始化
- `rendererType` 拼写不对

### 为什么 `model_json` 显示 missing model

通常是：

- `model` 路径错误
- `variant` 不存在
- 模型资源没有被正常加载
