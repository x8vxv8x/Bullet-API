# 渲染扩展

## 先分清边界

渲染扩展属于客户端扩展面。

你应该依赖的是：

- `RendererRegistry`
- `LaserRendererRegistry`
- `IBulletRenderer`
- `ILaserRenderer`

你不应该依赖的是：

- `ClientDanmakuCache`
- `ClientLaserCache`
- `ClientSummonCache`
- `RenderHandler`

前者是公开入口，后者是内部实现。

## 两类扩展方式

### 1. 复用现有渲染器

适合：

- 不想写新的客户端渲染代码
- 只是换模型、换颜色、换参数

做法：

- 直接设置 `rendererType`
- 通过 `customData` 传参数

说明：

- 当前版本里的 `customData` 已经是本 API 自己的轻量参数载荷，不再直接依赖 `NBTTagCompound`
- 使用方式仍然保持 `set("key", value)` 这类扁平键值写法
- 渲染器应把它理解成“高频参数容器”，不要把它当通用树状存档结构来设计

### 2. 注册新的渲染器类型

适合：

- 需要新的视觉算法
- 需要特殊几何、动画、材质逻辑

做法：

- 实现对应渲染接口
- 在客户端初始化时注册
- 在 builder 或 definition 里使用新的 `rendererType`

## 点弹幕渲染器

公开入口：

- `RendererRegistry`
- `IBulletRenderer`

内置类型：

- `billboard`
- `point`
- `model_json`

## 激光渲染器

公开入口：

- `LaserRendererRegistry`
- `ILaserRenderer`

内置类型：

- `laser_beam`
- `laser_blast`
- `laser_none`
- `laser_poly`

## 注册新的点弹幕渲染器

步骤：

1. 实现 `IBulletRenderer`
2. 在客户端初始化阶段注册到 `RendererRegistry`
3. 在 `BulletBuilder` 或 `SummonSpec` 中使用对应 `rendererType`

示例：

```java
RendererRegistry.register("my_renderer", data -> new MyRenderer());
```

注意：

- 注册逻辑只能放客户端
- 不要在通用服务端代码里直接引用客户端渲染类

## 注册新的激光渲染器

步骤：

1. 实现 `ILaserRenderer`
2. 注册到 `LaserRendererRegistry`
3. 在 `LaserBuilder` 中使用对应 `rendererType`

示例：

```java
LaserRendererRegistry.register("my_laser", data -> new MyLaserRenderer());
```

## 复用 `model_json`

`model_json` 会从 `customData` 读取这些常见字段：

- `model`
- `variant`
- `scale`
- `rot_mode`
- `tint`

示例：

```java
BulletApi.builder(world)
    .position(pos)
    .velocity(vel)
    .rendererType("model_json")
    .set("model", "minecraft:furnace")
    .set("variant", "inventory")
    .set("scale", 0.45f)
    .set("rot_mode", "velocity")
    .set("tint", 0x66CCFF)
    .spawn();
```

如果召唤物想复用同一套表现，也可以在 `SummonSpec` 中设置相同字段。

## `model_json` 常见旋转模式

- `velocity`
  - 按速度方向旋转
- `face_camera`
  - 始终朝向摄像机
- `fixed`
  - 使用固定朝向

## 激光视觉参数

激光渲染器通常通过 `customData` 读取参数。

例如 `laser_poly` 常见字段：

- `alpha`
- `poly_sides`
- `core_scale`
- `shell_scale`
- `pulse_amp`
- `pulse_speed`
- `shell_color`
- `shell_color_end`

例如 `laser_blast` 常见字段：

- `segment_len`
- `core_scale`
- `shell_scale`
- `shell_color`
- `shell_color_end`

## 推荐做法

- 视觉参数尽量用 `customData` 传
- 命中和伤害逻辑留在服务端 API / SPI 里处理
- 不要让渲染器承担战斗规则
- 参数尽量保持扁平键值结构，便于同步层做紧凑编码

## 常见问题

### 为什么 `rendererType` 没生效

通常是：

- 该类型没有注册
- 注册只发生在客户端，但没有在客户端初始化阶段执行
- `rendererType` 名字拼错

### 为什么 `model_json` 显示 missing model

通常是：

- `model` 路径错误
- `variant` 不存在
- 资源没有正确加载
