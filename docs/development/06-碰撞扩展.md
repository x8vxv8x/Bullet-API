# 碰撞扩展

## 先分清三层职责

当前版本里，“碰撞”不是一个单点概念，而是三层组合：

### 1. 几何是否命中

由：

- `ICollisionShape`

负责。

### 2. 这次是否允许碰撞

由局部过滤负责：

- `IBulletCollisionFilter`
- `ILaserCollisionFilter`

### 3. 阵营/关系上是否允许伤害

由全局关系解析负责：

- `ICombatRelationResolver`
- `CombatRelationResolverRegistry`

这样拆开以后，附属 mod 作者就不必把所有逻辑都塞进碰撞形状里。

## `ICollisionShape`

当前没有 `CollisionShapeRegistry`。

碰撞形状的扩展方式是：

- 实现 `ICollisionShape`
- 在 `BulletBuilder` 或 `SummonDefinition` 中直接传实例

这是一种代码型扩展点，而不是字符串注册型扩展点。

### 主要方法

- `getBroadphaseRadius()`
  - 粗筛半径
- `canCollideWith(Entity entity)`
  - 廉价快速过滤
- `intersects(Vec3d shapePos, Entity entity)`
  - 精确几何检测
- `intersects(double x, double y, double z, Entity entity)`
  - 热路径友好的坐标重载
- `checkCollision(...)`
  - 统一入口，通常调用方会走这个方法

## 内置形状

### `SphereShape`

适合：

- 普通点弹
- 召唤物本体碰撞

### `AABBShape`

适合：

- 方盒型弹幕
- 某些近战区域判定

## 自定义碰撞形状流程

1. 实现 `ICollisionShape`
2. 给出合理的 `getBroadphaseRadius()`
3. 在 `canCollideWith(...)` 中做廉价过滤
4. 在 `intersects(...)` 中实现精确检测
5. 将实例传给 builder 或定义

示例：

```java
public class MyShape implements ICollisionShape {
    @Override
    public double getBroadphaseRadius() {
        return 2.0D;
    }

    @Override
    public boolean intersects(double x, double y, double z, Entity entity) {
        // 自定义判定
        return false;
    }
}
```

## 在点弹幕中使用

```java
BulletApi.builder(world)
    .position(pos)
    .velocity(vel)
    .collisionShape(new MyShape())
    .spawn();
```

## 在召唤物中使用

```java
SummonDefinition.builder("modid:my_summon")
    .collisionShape(new MyShape())
    .bodyCollisionIntervalTicks(2)
    .build();
```

## 局部过滤

如果你不是想改几何，而是想改“打不打这个目标”，不要优先改 shape，应该先看：

- `IBulletCollisionFilter`
- `ILaserCollisionFilter`

适合：

- 只打玩家
- 不打主人
- 不打带某标签的实体
- 对某类目标临时免疫

## 全局关系解析

如果你想统一控制：

- 友伤
- 阵营
- 来自别的 mod 的全局关系

应使用：

- `ICombatRelationResolver`
- `CombatRelationResolverRegistry.register(...)`

这比把阵营逻辑塞进每个 builder 更适合做公共兼容层。

## 事件层

命中以后如果你想观察或拦截处理，可以用：

- `BulletCollisionEvent`
- `LaserCollisionEvent`

这层更适合做：

- 统计
- 特效联动
- 全局取消伤害
- 调试输出

## 性能建议

- 尽量实现 `getBroadphaseRadius()`
  - 让系统先做粗筛，避免无意义全量候选遍历
- 热路径下优先实现 `intersects(double x, double y, double z, Entity entity)`
  - 减少临时 `Vec3d` 分配
- `canCollideWith(...)` 里尽量只做廉价过滤
  - 例如类型过滤、无敌过滤、明显无效目标过滤
- 不要把复杂阵营规则塞进 shape
  - 这会让几何层和规则层耦合

## 为什么现在不做形状注册表

当前不引入注册表是合理的，因为：

- 大多数形状本质上是代码逻辑，不是简单参数模板
- 直接传实例更灵活
- 对性能也更友好

只有当未来明确需要：

- 数据驱动配置
- 编辑器可视化
- 字符串反序列化形状

再考虑注册表会更合适。
