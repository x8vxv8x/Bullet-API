# 碰撞扩展

## 当前扩展方式

当前 BulletAPI 没有 `CollisionShapeRegistry`。

碰撞箱扩展方式是：

- 实现 `ICollisionShape`
- 在点弹幕或召唤物定义中直接传实例

这意味着碰撞扩展目前属于代码型扩展，而不是字符串注册型扩展。

## 核心接口

接口：

- `ICollisionShape`

主要方法：

- `getBroadphaseRadius()`
  - 粗筛半径
- `canCollideWith(Entity entity)`
  - 快速过滤
- `intersects(Vec3d shapePos, Entity entity)`
  - 精确几何检测
- `intersects(double x, double y, double z, Entity entity)`
  - 坐标重载，适合热路径减少对象分配
- `checkCollision(...)`
  - 统一碰撞入口

## 内置形状

### `SphereShape`

球形碰撞箱。

适合：

- 普通点弹
- 本体碰撞召唤物

### `AABBShape`

轴对齐包围盒碰撞箱。

适合：

- 方盒型弹幕
- 某些近战挥击型判定

## 自定义碰撞箱流程

1. 实现 `ICollisionShape`
2. 根据需要实现 `canCollideWith(...)`
3. 实现精确几何检测
4. 将实例传给 Builder 或 `SummonDefinition`

示意：

```java
public class MyShape implements ICollisionShape {
    @Override
    public double getBroadphaseRadius() {
        return 2.0D;
    }

    @Override
    public boolean intersects(double x, double y, double z, Entity entity) {
        // 自定义判定
        return false;
    }
}
```

## 在点弹幕中使用

```java
BulletApi.builder(world)
    .position(pos)
    .velocity(vel)
    .collisionShape(new MyShape())
    .spawn();
```

## 在召唤物中使用

```java
builder.collisionShape(new MyShape())
       .bodyCollisionIntervalTicks(2);
```

## 性能建议

- 尽量实现 `getBroadphaseRadius()`
  - 让系统先做粗筛，避免全量遍历
- 热路径下优先实现坐标版 `intersects(double x, double y, double z, Entity entity)`
  - 减少 `Vec3d` 临时对象分配
- `canCollideWith(...)` 里尽量先做廉价过滤
  - 例如过滤创造玩家、非 `LivingBase`、特定阵营

## 何时考虑未来增加注册表

当前没有碰撞箱注册表是合理的，因为：

- 自定义形状通常是代码逻辑，不只是参数配置
- 绝大多数扩展通过实现接口即可完成

只有当未来要支持：

- 数据驱动模板
- 编辑器可视化配置
- 运行时按字符串反序列化形状

才值得考虑增加碰撞箱注册表。
