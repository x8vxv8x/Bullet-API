# 召唤物开发

## 入口

召唤物开发入口：

```java
SummonApi.builder(world)
```

注册定义或蓝图：

```java
SummonApi.registerDefinition(definition);
SummonApi.registerBlueprint(new MySummonBlueprint());
```

对应公开类型：

- `SummonApi`
- `SummonBuilder`
- `SummonDefinition`
- `Battlefield`
- `SummonHandle`
- `SummonSnapshot`
- `AbstractSummonBlueprint`

## 先理解召唤物的定位

当前版本里，召唤物更像“持续运行的战斗单元”，而不是单纯带模型的弹幕。

它由几部分组合而成：

- 定义
  - `SummonDefinition`
- 目标选择
  - `ISummonTargetSelector`
- 移动控制
  - `ISummonMoveController`
- 攻击逻辑
  - `ISummonAttackPattern`
- 编队锚点
  - `IFormationStrategy`

这套结构很适合附属 mod 自己拼出新玩法。

## 两种开发方式

### 1. 定义/蓝图注册

适合正式内容、复用内容、可被别处引用的召唤物。

常用基类：

- `AbstractSummonBlueprint`
- `AbstractOrbitingSummonBlueprint`
- `AbstractContactSummonBlueprint`

### 2. 生成时覆写

适合：

- 测试
- 临时技能
- 基于现有定义做一次性变体

```java
SummonApi.builder(world)
    .owner(player)
    .definition("bulletapi:ram_wisp")
    .position(pos)
    .slotCost(2)
    .damage(5.0f)
    .spawn();
```

## 召唤物的正式扩展点

### 应优先通过 SPI 接入的部分

- 选谁作为目标：`ISummonTargetSelector`
- 怎么移动：`ISummonMoveController`
- 怎么攻击：`ISummonAttackPattern`
- 在主人周围怎么编队：`IFormationStrategy`

### 应通过 Public API 使用的部分

- 注册定义：`SummonApi.registerDefinition(...)`
- 注册蓝图：`SummonApi.registerBlueprint(...)`
- 生成实例：`SummonApi.builder(...).spawn()` / `spawnHandle()`
- 控制单个实例：`SummonApi.handle(...)`
- 查世界对象集合：`Battlefield.of(world).summons()`
- 查槽位：`SummonApi.getPlayerUsedSlots(...)`、`getPlayerMaxSlots(...)`

### 应通过 Event 观察的部分

- 生成/移除：`SummonSpawnEvent`、`SummonRemoveEvent`
- 状态变化：`SummonStateChangedEvent`
- 目标变化：`SummonTargetChangedEvent`
- 槽位变化：`SummonSlotChangedEvent`

## 本体碰撞该怎么理解

这点和旧文档不同：

- 召唤物本体碰撞由运行时统一处理
- 当前没有公开的“召唤物本地 body hit callback”接口
- 外部若要观察或修改召唤物本体命中，应监听 `BulletCollisionEvent`

原因是召唤物本体在运行时上复用了统一碰撞链路，外部系统可以通过 `CollisionContext.attackSource` 区分来源。

`CollisionContext` 里可以用：

- `isSummonSource()`
- `isSummonBody()`
- `isSummonChildBullet()`
- `isSummonChildLaser()`

这意味着：

- 召唤物本体命中联动应走事件
- 召唤物主动攻击玩法应主要通过 `attackPattern`、子弹、激光来扩展

## Builder / Handle / Battlefield / Snapshot

## 当前版本的运行时强规范

召唤物当前版本不是“完全自由脚本”，而是有两条正式的运行时底线：

### 0. 主人命令和 summon 当前目标是两层结构

当前版本里：

- 主人命令目标存在 `SummonManager` 内的玩家命令表
- summon 本地只保留“自己当前实际采纳的目标”

也就是说：

- `setTarget(...)` 默认写入的是主人命令
- summon 会在 tick 中读取主人命令
- 然后再决定自己是否采纳成当前 `COMMAND` 目标

### 1. 无有效目标时，必须进入主人附近自动巡航

- 召唤物没有有效目标时，运行时会调用无目标运动逻辑
- 该逻辑必须负责主人附近的自动巡航 / 跟随
- 巡航路径可以自定义，但不能让 summon 进入未定义悬停状态

### 2. `leashRange` 超距恢复优先级高于命令目标

- 只要 summon 与主人距离超过 `leashRange`
- 当前目标会先失效
- 当前命令目标也会先失效
- 本 tick 直接切回无目标运动逻辑

这意味着：

- `setTarget(...)` 不是无限期强制追击
- 命令目标不能突破超距恢复
- 超距恢复完成后，summon 会重新回到主人附近自动巡航

### 3. 命令目标只保留一个有效槽位

- 同一个主人在任意时刻只保留一个有效命令目标
- 不同 tick 内写入新的命令目标时，始终取最新的那个
- 同一 tick 内若出现多个命令目标候选，玩家命令表会随机保留一个
- 即使主人当前存在命令目标，summon 也只会在该目标落入自身 `followRange` 时才采纳
- 不在 `followRange` 内的命令目标，会被视为当前 summon 不可采纳，并继续走自动索敌或无目标巡航

### 4. summon 可以声明是否接受主人命令

当前版本通过 `commandResponsePolicy` 表达 summon 对主人命令的响应方式：

- `STRICT_LOCK`
  - 默认模式
  - 允许把主人命令采纳为当前 `COMMAND` 目标
- `IGNORE_COMMAND`
  - 完全忽略主人命令
- `COMBAT_ONLY`
  - 只有 summon 已进入战斗状态时，才允许采纳主人命令

## MoveController 新骨架

当前版本的 `ISummonMoveController` 必须实现两个入口：

- `tickNoTargetMovement(SummonContext context)`
- `tickCombatMovement(SummonContext context)`

运行时会这样调度：

- 没有有效目标：调用 `tickNoTargetMovement(...)`
- 有有效目标且未触发超距恢复：调用 `tickCombatMovement(...)`

其中：

- 回归恢复不是单独入口
- 回归恢复属于 `tickNoTargetMovement(...)` 的一部分
- 该方法内部需要自己处理“超距拉回 -> 主人附近巡航”的平滑过渡

### Builder

负责生成实例。

常见用法：

```java
SummonHandle handle = SummonApi.builder(world)
    .owner(player)
    .definition("bulletapi:ram_wisp")
    .position(pos)
    .spawnHandle();
```

说明：

- `owner(...)` 必填
- `position(...)` 选填
- 不传 `position(...)` 时，会使用 owner 附近的默认出生点

### Handle

负责控制单个召唤物。

常用方法：

- `setPosition(...)`
- `setVelocity(...)`
- `setMotion(...)`
- `setLife(...)`
- `setTarget(...)`
- `clearTarget()`
- `retarget()`
- `returnToOwner()`
- `setState(...)`
- `remove()` / `despawn()`
- `snapshot()`

说明：

- `setTarget(...)` / `clearTarget()` 当前默认操作的是主人命令目标
- summon 本地是否真的切换到该目标，要等运行时在 tick 中完成采纳判断
- 如果主人命令仍然有效，`retarget()` 的本地自动索敌结果会在后续 tick 被主人命令重新覆盖

### Battlefield

负责查世界中的召唤物集合。

```java
Battlefield.Summons summons = Battlefield.of(world).summons();

int count = summons.count();
List<Integer> ids = summons.ids();
List<SummonSnapshot> all = summons.all();
SummonSnapshot one = summons.get(id);
SummonHandle handle = summons.handle(id);
List<SummonSnapshot> owned = summons.ownedBy(player.getUniqueID());
```

### Snapshot

`SummonSnapshot` 是精简只读状态，不负责控制。

适合：

- 调试输出
- 事件联动
- UI / 统计读取

当前主要字段：

- `id`
- `definitionId`
- `ownerId`
- `position`
- `velocity`
- `life`
- `damage`
- `state`
- `targetEntityId`
- `targetSource`
- `slotCost`
- `formationIndex`

其中 `targetSource` 用来区分当前目标来自：

- `AUTO`
  - 自动索敌
- `COMMAND`
  - 当前 summon 已采纳主人命令
- `SCRIPT`
  - summon 自身行为逻辑
- `NONE`
  - 当前没有目标

## 运行时模式与参数

当前版本已经移除了旧的 summon 命令队列。

不再推荐也不再支持：

- `SummonCommand`
- `sendCommand(...)`
- `supportsCommand(...)`
- `commandHandler(...)`

现在的做法是：

- 外部直接通过 `SummonHandle` 写运行时模式和参数
- 召唤物行为在 `SummonContext` 中读取这些值

注意：

- 运行时模式和参数适合表达 summon 的局部阶段与特殊行为
- 但不应该绕过当前版本的目标 / 超距恢复强规范
- 尤其不应依赖自定义参数来让 summon 在超出 `leashRange` 后继续执着追击旧目标

常用入口：

- `setMode(String)`
- `clearMode()`
- `setInt(String, int)`
- `setFloat(String, float)`
- `setBool(String, boolean)`
- `setString(String, String)`
- `clearParam(String)`

适合：

- 切换行为阶段
- 传入一次性事件数据
- 在事件里一行修改 summon 行为

示例：

```java
SummonApi.handle(world, summonId)
    .setMode("body_hit")
    .setInt("hit_entity_id", hit.getEntityId());
```

## 蓝图示例

```java
public class MySummonBlueprint extends AbstractContactSummonBlueprint {
    public MySummonBlueprint() {
        super("bulletapi:my_contact_summon");
    }

    @Override
    protected void configure(SummonDefinition.Builder builder) {
        builder
            .life(6000)
            .slotCost(1)
            .damage(4.0f)
            .texture("bulletapi:textures/entity/bullet.png")
            .color(0xFFAA66)
            .size(0.6f)
            .collisionShape(new SphereShape(0.3))
            .bodyCollisionIntervalTicks(2)
            .moveController(new RamStrikeMoveController());
    }
}
```

## 两种常见高级用法

### 静止陷阱 / 地雷

适合这样写：

- `position(...)` 指定落点
- `moveController(...)` 每 tick 保持静止
- `collisionShape(...)` 提供碰撞箱
- 监听 `BulletCollisionEvent` 处理踩中效果

### 母机 / 炮台 / 召唤节点

适合这样写：

- summon 负责移动、跟随、索敌
- `attackPattern(...)` 负责生成子弹、激光，或者进一步生成别的 summon
- 如需切换阶段，可用 `setMode(...)` 和运行时参数控制

## MoveController 写法建议

当前版本推荐按下面方式组织移动逻辑：

### `tickNoTargetMovement(...)`

负责：

- 超出 `leashRange` 后的恢复
- 主人附近自动巡航
- 从恢复态平滑过渡回巡航态

### `tickCombatMovement(...)`

负责：

- 对当前有效目标的接近、绕行、冲刺或压位
- 只处理战斗相关位移

这意味着：

- 不要再把“有没有目标”“要不要回主人附近”全部揉进一个旧的 `tickMovement(...)`
- 当前版本里，无目标运动和战斗运动是两个正式的运行时入口

## 常见问题

### 为什么召唤失败

先检查：

- 是否在服务端生成
- 是否设置了 `owner`
- 定义是否存在
- 槽位是否足够

### 为什么召唤物存在但不攻击

通常是：

- 没有目标
- `targetSelector` 没选中目标
- `attackRange` 太小
- `attackPattern` 为空

### 为什么本体不撞人

通常是：

- 没有 `collisionShape`
- `bodyCollisionIntervalTicks` 过大
- `moveController` 没有让它真正接近目标
- 阵营关系解析拒绝了目标

### 为什么事件里改 summon 行为没生效

优先检查：

- 是否拿到了正确的 summon id
- 是否在服务端调用 `SummonHandle`
- `mode` / 参数 key 是否和行为层读取的一致
- 是否被后续同 tick 写入覆盖了
