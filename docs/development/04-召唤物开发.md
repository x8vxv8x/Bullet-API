# 召唤物开发

## 入口

召唤物开发入口：

```java
SummonApi.builder(world)
```

注册定义或蓝图：

```java
SummonApi.registerDefinition(definition);
SummonApi.registerBlueprint(new MySummonBlueprint());
```

对应公开类型：

- `SummonApi`
- `SummonBuilder`
- `SummonDefinition`
- `Battlefield`
- `SummonHandle`
- `SummonSnapshot`
- `AbstractSummonBlueprint`

## 先理解召唤物的定位

当前版本里，召唤物更像“持续运行的战斗单元”，而不是单纯带模型的弹幕。

它由几部分组合而成：

- 定义
  - `SummonDefinition`
- 目标选择
  - `ISummonTargetSelector`
- 移动控制
  - `ISummonMoveController`
- 攻击逻辑
  - `ISummonAttackPattern`
- 编队锚点
  - `IFormationStrategy`

这套结构很适合附属 mod 自己拼出新玩法。

## 两种开发方式

### 1. 定义/蓝图注册

适合正式内容、复用内容、可被别处引用的召唤物。

常用基类：

- `AbstractSummonBlueprint`
- `AbstractOrbitingSummonBlueprint`
- `AbstractContactSummonBlueprint`

### 2. 生成时覆写

适合：

- 测试
- 临时技能
- 基于现有定义做一次性变体

```java
SummonApi.builder(world)
    .owner(player)
    .definition("bulletapi:ram_wisp")
    .position(pos)
    .slotCost(2)
    .damage(5.0f)
    .spawn();
```

## 召唤物的正式扩展点

### 应优先通过 SPI 接入的部分

- 选谁作为目标：`ISummonTargetSelector`
- 怎么移动：`ISummonMoveController`
- 怎么攻击：`ISummonAttackPattern`
- 在主人周围怎么编队：`IFormationStrategy`

### 应通过 Public API 使用的部分

- 注册定义：`SummonApi.registerDefinition(...)`
- 注册蓝图：`SummonApi.registerBlueprint(...)`
- 生成实例：`SummonApi.builder(...).spawn()` / `spawnHandle()`
- 控制单个实例：`SummonApi.handle(...)`
- 查世界对象集合：`Battlefield.of(world).summons()`
- 查槽位：`SummonApi.getPlayerUsedSlots(...)`、`getPlayerMaxSlots(...)`

### 应通过 Event 观察的部分

- 生成/移除：`SummonSpawnEvent`、`SummonRemoveEvent`
- 状态变化：`SummonStateChangedEvent`
- 目标变化：`SummonTargetChangedEvent`
- 槽位变化：`SummonSlotChangedEvent`

## 本体碰撞该怎么理解

这点和旧文档不同：

- 召唤物本体碰撞由运行时统一处理
- 当前没有公开的“召唤物本地 body hit callback”接口
- 外部若要观察或修改召唤物本体命中，应监听 `BulletCollisionEvent`

原因是召唤物本体在运行时上复用了统一碰撞链路，外部系统可以通过 `CollisionContext.attackSource` 区分来源。

`CollisionContext` 里可以用：

- `isSummonSource()`
- `isSummonBody()`
- `isSummonChildBullet()`
- `isSummonChildLaser()`

这意味着：

- 召唤物本体命中联动应走事件
- 召唤物主动攻击玩法应主要通过 `attackPattern`、子弹、激光来扩展

## Builder / Handle / Battlefield / Snapshot

### Builder

负责生成实例。

常见用法：

```java
SummonHandle handle = SummonApi.builder(world)
    .owner(player)
    .definition("bulletapi:ram_wisp")
    .position(pos)
    .spawnHandle();
```

说明：

- `owner(...)` 必填
- `position(...)` 选填
- 不传 `position(...)` 时，会使用 owner 附近的默认出生点

### Handle

负责控制单个召唤物。

常用方法：

- `setPosition(...)`
- `setVelocity(...)`
- `setMotion(...)`
- `setLife(...)`
- `setTarget(...)`
- `clearTarget()`
- `retarget()`
- `returnToOwner()`
- `setState(...)`
- `remove()` / `despawn()`
- `snapshot()`

### Battlefield

负责查世界中的召唤物集合。

```java
Battlefield.Summons summons = Battlefield.of(world).summons();

int count = summons.count();
List<Integer> ids = summons.ids();
List<SummonSnapshot> all = summons.all();
SummonSnapshot one = summons.get(id);
SummonHandle handle = summons.handle(id);
List<SummonSnapshot> owned = summons.ownedBy(player.getUniqueID());
```

### Snapshot

`SummonSnapshot` 是精简只读状态，不负责控制。

适合：

- 调试输出
- 事件联动
- UI / 统计读取

当前主要字段：

- `id`
- `definitionId`
- `ownerId`
- `position`
- `velocity`
- `life`
- `damage`
- `state`
- `targetEntityId`
- `slotCost`
- `formationIndex`

## 运行时模式与参数

当前版本已经移除了旧的 summon 命令队列。

不再推荐也不再支持：

- `SummonCommand`
- `sendCommand(...)`
- `supportsCommand(...)`
- `commandHandler(...)`

现在的做法是：

- 外部直接通过 `SummonHandle` 写运行时模式和参数
- 召唤物行为在 `SummonContext` 中读取这些值

常用入口：

- `setMode(String)`
- `clearMode()`
- `setInt(String, int)`
- `setFloat(String, float)`
- `setBool(String, boolean)`
- `setString(String, String)`
- `clearParam(String)`

适合：

- 切换行为阶段
- 传入一次性事件数据
- 在事件里一行修改 summon 行为

示例：

```java
SummonApi.handle(world, summonId)
    .setMode("body_hit")
    .setInt("hit_entity_id", hit.getEntityId());
```

## 行为实现里可以从 SummonContext 读什么

当你在 `ISummonMoveController`、`ISummonAttackPattern`、`ISummonTargetSelector` 里实现逻辑时，可以直接读取 `SummonContext`。

### 基础运行时对象

- `world`
- `summon`
- `owner`
- `definition`
- `worldTick`

### 目标与空间信息

- `getTarget()`
- `setTarget(...)`
- `getOwnerCenter()`
- `getTargetCenter()`
- `getOwnedSummonCount()`

### 运行时模式

- `getMode()`
- `setMode(...)`
- `clearMode()`

### 配置与参数读取

- `hasParam(key)`
- `hasRuntimeParam(key)`
- `getInt(...)`
- `getFloat(...)`
- `getBool(...)`
- `getString(...)`

### 运行时参数写入

- `setInt(...)`
- `setFloat(...)`
- `setBool(...)`
- `setString(...)`
- `clearParam(...)`

### 一次性事件参数

如果某个参数只想消费一次，用：

- `consumeInt(...)`
- `consumeFloat(...)`
- `consumeBool(...)`
- `consumeString(...)`

适合：

- body hit 事件
- 技能触发器
- 单次转阶段信号

## 蓝图示例

```java
public class MySummonBlueprint extends AbstractContactSummonBlueprint {
    public MySummonBlueprint() {
        super("bulletapi:my_contact_summon");
    }

    @Override
    protected void configure(SummonDefinition.Builder builder) {
        builder
            .life(6000)
            .slotCost(1)
            .damage(4.0f)
            .texture("bulletapi:textures/entity/bullet.png")
            .color(0xFFAA66)
            .size(0.6f)
            .collisionShape(new SphereShape(0.3))
            .bodyCollisionIntervalTicks(2)
            .moveController(new RamStrikeMoveController());
    }
}
```

## 两种常见高级用法

### 静止陷阱 / 地雷

适合这样写：

- `position(...)` 指定落点
- `moveController(...)` 每 tick 保持静止
- `collisionShape(...)` 提供碰撞箱
- 监听 `BulletCollisionEvent` 处理踩中效果

### 母机 / 炮台 / 召唤节点

适合这样写：

- summon 负责移动、跟随、索敌
- `attackPattern(...)` 负责生成子弹、激光，或者进一步生成别的 summon
- 如需切换阶段，可用 `setMode(...)` 和运行时参数控制

## 常见问题

### 为什么召唤失败

先检查：

- 是否在服务端生成
- 是否设置了 `owner`
- 定义是否存在
- 槽位是否足够

### 为什么召唤物存在但不攻击

通常是：

- 没有目标
- `targetSelector` 没选中目标
- `attackRange` 太小
- `attackPattern` 为空

### 为什么本体不撞人

通常是：

- 没有 `collisionShape`
- `bodyCollisionIntervalTicks` 过大
- `moveController` 没有让它真正接近目标
- 阵营关系解析拒绝了目标

### 为什么事件里改 summon 行为没生效

优先检查：

- 是否拿到了正确的 summon id
- 是否在服务端调用 `SummonHandle`
- `mode` / 参数 key 是否和行为层读取的一致
- 是否被后续同 tick 写入覆盖了
